# [0단계] 설치 — 최초 1회

트리거: `scripts/doctor.sh`가 `다음 할 일: 설치`를 냈을 때, 또는 "릴스 편집 세팅해줘". 끝나면 doctor를 다시 돌려 "학습"이면 바로 1단계로.
없는 것만 설치하고 있으면 "있음"으로 넘어간다. 컴퓨터마다 다른 값과 실행 결과는 `환경.md`에 적는다(이 파일에는 적지 않는다).
설치는 AI가 전부 한다 — 도구는 `scripts/setup.sh`가 자동으로 깐다(doctor가 먼저 돌린다. 설치한 것은 "설치함:" 줄, 사람 손이 필요한 것은 "→ 사용자:" 줄). 아래 (1) 표는 setup.sh가 못 깐 것을 손으로 채울 때의 기준이다. 사용자 손이 필요한 것은 세 가지뿐이다 — 설치 창의 "설치"·"허용" 누르기, 비밀번호, 키 넣기. 그때만 쉬운 말로 한 줄 부탁하고 "했어요"를 받아 이어 간다.

## (0) 운영체제 — doctor가 알아본다

| 컴퓨터 | 받아쓰기 | HDR→SDR | 얼굴·인물 인식 | CapCut 자동 내보내기·화면 검수 |
|---|---|---|---|---|
| 맥(애플 칩) — 기본 | mlx_whisper | avconvert | 맥 Vision(swift) | 됨(영어판 CapCut) |
| 맥(인텔) | faster-whisper | avconvert | 맥 Vision(swift) | 됨 |
| 윈도우 (미검증) | faster-whisper | ffmpeg zscale(gyan 전체판에 있음) | opencv(얼굴) · rembg(인물, 없으면 오려내기 생략) | 안 됨 → 사용자가 내보내고 `final_check.sh`로 대조만 |

- 윈도우는 클로드 코드가 쓰는 Git Bash 위에서 `.sh`가 돈다. `python3`이 가짜(스토어 안내)일 수 있어 `scripts/env.sh`의 `$PY`로 부른다.
- 윈도우 분기는 실제 윈도우에서 아직 시험하지 않았다. 처음 윈도우에서 돌리면 doctor 결과와 막힌 곳을 `환경.md` 설치 기록에 적는다. 특히 확인할 것: whisper-ctranslate2의 단어 시간 출력, zscale 톤매핑 색감, CapCut 프로젝트 폴더 위치(다르면 `CAPCUT_DRAFT_DIR` 환경변수로 덮어쓴다).
- 이 스킬이 꾸러미로 설치된 것이면(스킬 폴더에 `remotion/`·`sfx/files/`가 있음) 아래 (1) 8번·(2)는 "꾸러미에서" 방식으로 한다.

## (2) 효과음 팔레트 — 프로젝트는 AI가 만든다

사용자에게 프로젝트를 만들게 하지 않는다. 사용자 손이 필요한 건 "CapCut 효과음 창고에서 소리 고르기"뿐이다(창고는 CapCut 화면 안에서만 열린다).

**꾸러미에서 받은 경우(스킬 폴더에 `sfx/files/*.mp3`와 `sfx/sfx-catalog.md`가 이미 있음)**: 소리 고르기가 필요 없다. CapCut이 꺼진 것을 확인하고 `python3 scripts/sfx_register.py` — 소리 파일을 이 컴퓨터 CapCut의 [효과음팔레트] 프로젝트에 넣고 `sfx/templates/*.json`을 이 컴퓨터 경로로 다시 뜬다(템플릿 안 소리 경로는 CapCut 캐시라 컴퓨터마다 다르다). 끝나면 아래 4번 호환성 시험만 한다. 사용자가 소리를 더 넣고 싶으면 그때 아래 1~3번.

1. 먼저 [정답지]와 사용자가 직접 편집한 다른 프로젝트에서 CapCut 효과음을 찾는다. `capcut materials <프로젝트> --type audios`에서 목소리 원본이 아닌 소리. `환경.md`의 "참조하지 않는 것"에 든 프로젝트는 제외.
 - 있으면 그 프로젝트에서 바로 3번으로(원본은 읽기만).
2. 없으면 CapCut이 꺼진 것을 확인하고(맥: `pgrep -x CapCut`) `capcut init [효과음팔레트] --ratio 9:16`, `capcut init [테스트프로젝트] --ratio 9:16`로 만든 뒤 이렇게만 부탁한다:
 > CapCut을 열면 "효과음팔레트" 프로젝트가 있습니다. 열어서 효과음 메뉴에서 자주 쓰는 소리(우쉬, 쿵, 띠링, 띵, 돈 등)를 하나씩 올리고, 소리 크기를 평소대로 맞춘 뒤 저장하고 CapCut을 꺼 주세요.
 - `capcut init` 프로젝트가 CapCut에서 열리는지는 따로 확인받지 않는다. 사용자가 "안 열린다"고 할 때만 같은 이름으로 직접 만들어 달라고 한다.
3. 효과음 정리 — CapCut 효과음 이름은 여러 언어가 섞이고 용도를 알 수 없으므로 AI가 새로 이름을 붙인다. 사용자에게 이름을 바꿔 달라고 하지 않는다.
 - 세 명령으로 끝난다 (처음이든 소리를 더 넣었든 같다. 이미 뽑은 소리는 건너뛰고 번호를 이어 붙인다):
 ```
 python3 scripts/sfx_extract.py <팔레트 프로젝트> sfx # 목록·소리 사본 → palette_raw.json, palette_new.json
 python3 scripts/sfx_listen.py sfx/palette_new.json sfx/palette_heard_new.json # 재고 Gemini가 듣고 이름 붙임
 python3 scripts/sfx_catalog.py <팔레트 프로젝트> sfx sfx/palette_heard_new.json # 템플릿 + sfx-catalog.md
 ```
 - sfx_extract: 소리 파일이 CapCut 임시 보관함에 있어 지워질 수 있으니 `sfx/files/NN.확장자`로 사본을 둔다.
 - sfx_listen: ffmpeg로 길이·최고 음량·가장 커지는 시점·밝기를 재고, Gemini에게 파일을 직접 들려 사용자 언어 이름(예: 띵_전구)·들리는 소리·느낌·쓰는 순간·피할 때를 받는다.
 - sfx_catalog: 템플릿이 없는 소리만 `capcut save-template`, 목록 파일 `sfx/sfx-catalog.md`(번호, 이름, 이럴 때 쓴다, 피할 때, 들리는 소리, 느낌, 길이, 볼륨, 가장 큰 시점, 원래 CapCut 이름)를 다시 쓴다. 편집메뉴얼 9번은 이 이름으로 부른다.
 - CapCut이 켜져 있어도 읽기만 하므로 돌릴 수 있다. 다만 사용자가 저장하지 않은 소리는 안 보이니 "저장하셨나요?"를 먼저 확인한다.
4. 호환성 시험: [테스트프로젝트]에 `apply-template`로 2개를 0초·2초에 넣고 `capcut register <프로젝트> --materials --apply`로 소리를 등록한다(안 하면 CapCut 9 이상에서 "파일 없음"으로 뜰 수 있다). 왜 하는지 먼저 쉽게 설명한 뒤 요청:
 > 제가 CapCut 효과음을 직접 꺼내 쓸 수 있는지 시험하는 중입니다. CapCut에서 테스트 프로젝트를 열고 0초, 2초에 소리가 나는지 확인해 주세요.
5. 자동 내보내기 시험: `capcut export <폴더> --batch`는 폴더 안의 모든 프로젝트를 내보낸다. CapCut 프로젝트 폴더 전체에 돌리지 말고, 테스트 프로젝트 하나로만 시험한다.

## (3) 키 넣기

- 사용자가 번호 목록으로 답하면 "1." 같은 번호가 키 앞에 붙어 보인다. 번호는 떼고 넣는다.
- Gemini 키: `~/.config/watch/.env`의 `GEMINI_API_KEY=` 줄에 파일 편집으로 넣는다(명령줄에 키를 쓰지 않음). 같은 파일에 `WATCH_ENGINE="local"`, `WATCH_WHISPER_BACKEND="none"`.
 - 엔진이 auto면 키가 있는 순간 모든 영상(사용자 편집본 포함)이 구글로 올라간다. 레퍼런스 분석 때만 `--engine gemini`를 붙인다.
 - 받아쓰기가 auto면 OPENAI_API_KEY가 생겼을 때 소리를 OpenAI로 올린다. 받아쓰기는 mlx-whisper로 하므로 none.
- OpenAI 키: 셸 설정 파일(맥 기본 `~/.zshrc`)에 `export OPENAI_API_KEY=…`.
- 넣은 뒤 두 키 모두 실제로 한 번 호출해 정상 응답(200)인지 확인한다. 키 위치는 `환경.md`에 적고 키 값은 적지 않는다.

## (4) 끝에 모아서 묻기 (질문양식.md 형식)

- Gemini 키, GPT Image 키 (없을 때만)
- AI 나레이션(사용자 목소리로 읽는 소리)을 쓸지 — 쓴다면 fish.audio에서 본인 목소리 모델을 만들어 그 id를 받고(`환경.md` [나레이션 목소리]에 적음), API 키는 터미널에서 직접 넣게 안내한다(13번 줄의 명령, 채팅에 붙이지 않음). 넣은 뒤 `python3 scripts/narration.py say "시험 문장입니다" /tmp/n.wav`로 한 번 들어 본다. 안 쓴다면 넘어간다 — 나중에 나레이션을 고를 때 다시 묻는다. 추천: 쓸 계획이 있으면 지금 (키 없을 때만)
- 편집메뉴얼 기준이 될 레퍼런스 릴스 링크 3개 — 같은 폴더에 `/릴스대본기획`이 설치돼 있으면 먼저 `bash .claude/skills/릴스대본기획/lib/fetch.sh my_top 3`로 본인 상위 릴스를 뽑아 "이 3개로 할까요?"로 제안한다(링크를 찾아오게 하지 않는다)
- 직접 편집해서 마음에 들었던 CapCut 프로젝트 이름 (없으면 없다고 해도 된다고 설명 — 레퍼런스만으로 간다)
- (효과음이 없을 때만) 효과음팔레트에 효과음 담아 달라는 요청

답을 받으면 `환경.md`를 채우고 `bash scripts/doctor.sh --write-env`로 운영체제·받아쓰기 엔진을 적는다. 다시 doctor가 "학습"을 내면 1단계로.
