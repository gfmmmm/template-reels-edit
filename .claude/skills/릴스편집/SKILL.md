# 릴스편집

사용자의 촬영 원본을 편집메뉴얼 기준으로 편집한다. 사용자는 비개발자다. 터미널을 쓰게 하지 않고, 기술 용어는 쉬운 말로 푼다.
컴퓨터마다 다른 값(경로·정답지·레퍼런스·키 위치·운영체제)은 `환경.md` 한 곳에만 있다. 단계 파일의 `[대괄호]`는 거기서 찾는다.
맥(애플 칩)이 기본이고 윈도우에서도 돈다 — 운영체제 차이는 `scripts/env.sh`·`scripts/platform_util.py`가 스스로 가른다(받아쓰기·HDR 변환·얼굴 인식·CapCut 경로). 윈도우 분기는 실제 윈도우에서 아직 시험하지 않았다. 윈도우에서는 CapCut 내보내기와 화면 검수를 사용자가 직접 한다.

## 이 설치본에 대해 (깃허브 공개판)

- 이 스킬은 깃허브에서 내려받은 폴더의 `.claude/skills/릴스편집/`에 있다. 단계 파일에서 "팀 폴더"라고 부르는 곳은 이 폴더다. 맥인지 윈도우인지는 설치 때 정해지지 않고, 스킬이 불릴 때마다 `bash .claude/skills/릴스편집/scripts/doctor.sh`가 이 컴퓨터를 보고 맞춘다. 첫 응답은 언제나 doctor 의 마지막 줄("다음 할 일: 설치 / 학습 / 편집 가능")을 따른다.
- `환경.md`가 없으면 doctor 를 돌리기 전에 `환경.template.md`를 `환경.md`로 복사한다.
- 이 판에는 만든 사람의 학습분(`편집메뉴얼.md`·`presets/`·`brand.ts`)이 없다. 이 사용자의 레퍼런스·정답지로 1단계에서 새로 만든다. 단계 파일에 나오는 숫자 예시는 다른 계정의 값이라 그대로 가져다 쓰지 않는다.
- 효과음 소리 파일과 CapCut 글꼴은 다시 배포할 수 없어 들어 있지 않다. 0단계 (2)는 "꾸러미에서 받은 경우"가 아니라 1~3번 길로 간다. 사용자에게 소리를 고르게 할 때는 `sfx/추천효과음.md`의 "원래 CapCut 이름"을 CapCut 효과음 검색창에 치면 같은 소리가 나온다고 안내한다(8~12개면 충분, 다 고를 필요 없음). 자막 글꼴은 1단계에서 사용자 CapCut 글꼴로 정하고, Remotion 확인본용 글꼴 파일은 사용자가 가진 파일을 `계정자료/`에 둔다. 들어 있는 글꼴은 도현체(OFL) 하나다.
- 영상·결과물은 이 폴더 밖 `[결과루트]`에, Remotion 은 스킬의 `remotion/`을 `[Remotion폴더]`로 복사한 뒤 그 안에서 `npm install`(0단계). 이 폴더 안에 node_modules·영상을 두지 않는다.
- 새 버전: 사용자가 "업데이트 받아줘"라고 하면 폴더 맨 위에서 `bash update.sh`. 도구만 바뀌고 사용자가 키운 것(편집메뉴얼·환경·프리셋·효과음 등록분·계정자료·brand.ts)은 남는다.
- 사용자를 부르는 호칭은 쓰지 않는다. 존댓말. 키·비밀번호는 채팅에 적지 않고 "터미널에서 직접"으로 안내한다.

## 첫 응답 — 상태 진단으로 갈린다 (전체 진단은 컴퓨터마다 최초 1회)

어떤 요청이든 먼저 `bash [스킬폴더]/scripts/doctor.sh`를 돌린다. **이 컴퓨터에서 한 번 "편집 가능"을 통과했으면 doctor가 스스로 건너뛰고** 한 줄(통과한 날짜 + `다음 할 일: 편집 가능`)만 찍는다 — 1초. 그때는 사용자에게 상태를 말하지 않고 바로 요청 표로 간다. 전체 진단을 다시 도는 경우는 셋뿐이다: ① "릴스 편집 세팅해줘"·"편집메뉴얼 다시 만들어줘"처럼 세팅 자체를 요청했을 때 ② 편집 도중 도구가 안 돼서(받아쓰기·CapCut·Remotion 오류) 원인을 봐야 할 때 ③ 사용자가 "진단 다시 해"라고 했을 때 → `doctor.sh --force`. 통과표시는 `~/.cache/릴스편집/doctor_ok`(컴퓨터마다 따로. 스킬 폴더는 드라이브라 여러 컴퓨터가 같이 쓰므로 거기 두지 않는다). 처음이거나 통과표시가 없을 때(처음이면 설치 시간만큼) doctor는 ① 없는 도구를 `setup.sh`로 그 자리에서 설치하고(자가 수리) ② 드라이브 파일이 실제로 읽히는지 보고 ③ 남은 일을 `→ AI:` / `→ 사용자:` 줄로 낸다. `→ AI:` 줄은 묻지 않고 바로 하고, `→ 사용자:` 줄은 그 한 가지만 부탁한다. 마지막 줄이 상황을 정한다. 사용자에게는 "지금 상태"를 한 줄로만 말하고 그 상황의 파일로 바로 간다.

| doctor 마지막 줄 | 상황 | 여는 파일 |
|---|---|---|
| `다음 할 일: 설치` | 필요한 프로그램이 빠져 있다 | `0_설치.md` — AI가 전부 설치한다. 사람 손이 필요한 것(설치 창 확인, 키 넣기)만 그 자리에서 부탁 |
| `다음 할 일: 학습` | 프로그램은 있는데 이 계정 기준(편집메뉴얼·자막 모양·brand.ts·효과음 팔레트)이 비어 있다 | `1_편집메뉴얼만들기.md` — 왜 학습이 필요한지 쉬운 말로 설명하고 레퍼런스·정답지를 받아 진행 |
| `다음 할 일: 편집 가능` | 다 세팅됨 | 아래 요청 표대로 |

doctor가 "설치"인데 사용자가 편집을 요청했으면, 설치 → 학습 → 편집을 한 흐름으로 이어서 한다(단계마다 다시 부르게 하지 않는다). `--write-env`로 `환경.md`의 [운영체제]·[받아쓰기 엔진]을 채운다.

## 어느 파일을 언제 여나 (편집 가능 상태)

| 요청 | 여는 파일 |
|---|---|
| "릴스 편집 세팅해줘" (새 컴퓨터, 최초 1회) | `0_설치.md` → 끝나면 `1_편집메뉴얼만들기.md` |
| "편집메뉴얼 다시 만들어줘" | `1_편집메뉴얼만들기.md` |
| "정답지랑 비교해", "게시본이랑 비교해서 고쳐", "루프 돌려" (같은 원본으로 사람이 만든 게시본이 있을 때) | `5_정답지대조루프.md` — 블라인드 편집 → `릴스대조` 채점 → 공용/계정/이 영상만으로 나눠 고치기 → `rebuild.sh` → 90점 또는 정체까지 |
| "릴스 편집해줘 + 영상 파일" | `2_컷편집.md` → `3_효과.md` → `4_제출.md` 순서 |
| "이어서", "어디까지 했지" | `[결과루트]/<날짜_영상이름>/진행상황.md`부터 읽고 그 단계 파일 |
| "풀스크립트 줘" | `[결과폴더]/풀스크립트.md` (없으면 2단계 끝 규칙대로 만든다) |
| 아쉬운 점 피드백 | `4_제출.md` 6번 (갈 곳: brand.ts / presets / 편집메뉴얼) |

숫자 기준은 언제나 `편집메뉴얼.md`, 질문은 `질문양식.md` 형식으로 — 시작 질문은 채팅에 `## Q1.` 꼴로, 모호한 건 팝업(AskUserQuestion)으로.
도구는 전부 `scripts/`, 효과음은 `sfx/sfx-catalog.md`, 자막·이모지·라벨 모양은 `presets/`, 편집메뉴얼의 빈 틀은 `templates/편집메뉴얼_틀.md`.

## 흐름 요약

1. **컷편집 (2단계)** — 시작 질문(채팅: 영상 파일·대본·레퍼런스·소스 개수·화면 녹화·요청사항) → 확인 질문(팝업, 모호할 때만) → 전처리(HDR→SDR, 소리 -14 LUFS) → 덩어리별 받아쓰기 → 교정 대본·테이크 고르기·배속 → 대본을 받았으면 대본 대조 → 컷 설계·미리보기 → 숫자 점검 → `릴스검수` 2회 → CapCut 빈 프로젝트에 채우기 → 풀스크립트.md(잘라낸 것 포함). 중간 보고 없이 3단계로.
2. **효과 (3단계)** — 시작 때 화면 기록 파일·상단 제목·대본 대조에서 뺄 문장만 묶어서 묻는다 → 화면 계획 → 자막·확대 → 효과음 → CapCut 조립 → 확인본 → `릴스검수` 2회 → 승인 전 숫자 대조(`preview_match.py`) → 승인본 → CapCut 실물 검수.
3. **제출 (4단계)** — CapCut 실물이 승인본과 같아야 "완성". 브리핑 + 최종 풀스크립트 전문.

## 도구는 어디에 쓰나 — AI가 판단한다

사용자에게 도구를 묻거나 고르게 하지 않는다(초보자는 모른다). 대사·자료화면을 보고 AI가 아래 표대로 정하고, 쓴 도구는 4단계 최종 보고에서 알린다. 사용자가 먼저 빼라고 한 도구만 그 편집에서 쓰지 않는다.

| 도구 | 쓰는 곳 | 안 쓰는 곳 |
|---|---|---|
| CapCut | 자막·이모지·라벨·확대·전환·효과음·최종 조립 (사용자가 직접 고치기 쉬워야 하므로 여기에) | — |
| Remotion | 번호 장 카드, 앱 화면 장면, 퍼센트 막대, 보고서·흐름 같은 모션그래픽 | 자막·이모지(CapCut 몫) |
| GPT Image(최신 모델) | 아이콘으로도 안 되는 그림(상징 캐릭터, 비유 삽화)만 | 실제 화면·데이터를 그리는 일 |
| aside | 글꼴 찾기, 아이콘 받기, 대사 속 사실의 출처 찾기(영상당 3건 안쪽), 실제 웹 화면 캡처 자료화면(`scripts/aside_capture.sh`, 3_효과.md ③-A 4-1) | 시키지 않은 로그인 개인 화면 캡처, 화면 글·숫자 고치기 |
| Gemini | 레퍼런스 영상 설명(1단계), 효과음 이름 붙이기(설치) | 사용자 촬영 원본(구글로 올리지 않는다) |
| 받아쓰기(mlx_whisper / faster-whisper) | 모든 받아쓰기 — 컴퓨터 안에서만 | — |
| Fish Audio | 사용자 목소리로 학습한 AI 나레이션 — 안 찍힌 문장, 자료화면 설명(3_효과.md ③-0, 사용자가 고른 것만) | 사용자가 고르지 않은 문장, 다른 사람 목소리 |

## 늘 지키는 것 (사용자 지시)

- 좌우 소리는 항상 같은 크기(전처리에서 두 채널 섞기). 한쪽만 크게 들리면 안 된다.
- 원본은 건드리지 않는다. 변환본은 `[결과폴더]/media/`에 두고 옮기거나 지우지 않는다(CapCut이 경로를 기억).
- 받아쓰기 오인식만 고친다. 말의 내용·말투는 바꾸지 않는다. 화면 글·데이터는 지어내지 않는다.
- 대본과 촬영본이 다르면 촬영본이 기준이다. 다만 차이를 숨기지 않는다 — 안 찍힌 문장·새로 생긴 문장·표현이 바뀐 문장을 표로 보여 주고, 뺄 것만 사용자가 고른다(2_컷편집.md ②-1).
- 검수 에이전트 진행 상황은 말하지 않고, 결과 원문을 띄우지 않는다. 결과는 파일로, 보고 끝에 요약만.
- 2단계 뒤에는 중간 보고·재생 확인 요청 없이 3단계로. 판단이 갈린 컷은 진행상황.md에 모아 최종 보고에서.
- 컷편집 결과를 줄 때는 풀스크립트 전문을 같이 붙인다 — 대사·이모지·자료장면·상단 제목만, 뺀 문장은 제자리에 취소선(형식은 2_컷편집.md 끝).
- 확인본·최종본_고화질은 승인용 그림이다. 업로드용은 CapCut 실물에서만.
- CapCut이 켜져 있는 동안은 프로젝트 파일을 고치지 않는다(`platform_util.capcut_running`). 사용 중에 자동 클릭하지 않는다.

## 영상 보여 드리기

미리보기·승인본·비교 영상은 `open -a "QuickTime Player" <파일>`과 `open -R <파일>`(Finder에서 그 파일 표시)을 같이 한다. `open`만 하면 창이 안 떠서 사용자가 "다시 열어줘"를 반복했다(IMG_0519). 메시지에 파일 위치를 한 줄로.

## 알려진 함정

- **퍼센트는 막대로**: "N%"를 말하면 PercentBar(가운데, 그 값까지 차오름). 앱 장면 위 상시 막대는 없음.
- **AI 작업 화면은 말마다 한 컷**: RecScene shots(기준점·배율이 천천히 움직임) + "직접 조작" 말엔 control 그래픽 + "⚠ 실제 화면" 표시. 렌더 뒤 freezedetect로 멈춤 0 확인.

- **말끝 잘림은 받아쓰기로 못 잡는다**: 받아쓰기는 잘린 끝 음절을 채워 듣는다 → 컷 뒤 `edge_check.py`가 원본 소리로 말끝·마찰음 첫소리·앞 문장 꼬리 조각을 찾는다(`--fix` → cutplan 다시, 공용 76). 문장 경계 도구는 끝 단어 안 음절 사이에서 자르지 않는다.
