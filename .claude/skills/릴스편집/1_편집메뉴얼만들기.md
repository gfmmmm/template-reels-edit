# [1단계] 레퍼런스 분석 → 편집메뉴얼 — 최초 1회

트리거: `scripts/doctor.sh`가 `다음 할 일: 학습`을 냈을 때, 0단계 직후, 또는 "편집메뉴얼 다시 만들어줘".
순서: 수집 → 분석 → 문서 작성 → 질문 → 검수. 산출물은 `편집메뉴얼.md`, `presets/`, `[Remotion폴더]/src/brand.ts`. 경로·링크 등은 `환경.md`.
시작할 때 사용자에게 한 번 설명한다: "이 계정의 편집 기준(컷 길이·자막 모양·효과음 규칙 같은 숫자)을 레퍼런스 영상과 직접 편집한 프로젝트에서 재서 메뉴얼로 만듭니다. 한 번 만들면 그 뒤 편집은 전부 이 기준으로 합니다." 그리고 필요한 것(레퍼런스 3개, 정답지 프로젝트 이름)을 질문양식으로 한 번에 묻는다 — 0단계 (4)에서 이미 받았으면 묻지 않는다.

- 시작은 빈 틀에서: `templates/편집메뉴얼_틀.md`를 `편집메뉴얼.md`로 복사한다(이미 채워진 메뉴얼이 있으면 그 위에서 갱신). 틀에 "(기본)"으로 적힌 값은 여러 계정에서 공통으로 통한 경험값이다 — 레퍼런스·정답지에서 잰 값이 있으면 (레)/(정)으로 덮어쓰고, 잴 수 없을 때만 (기본)을 남긴다. "(채울 것)"은 반드시 채운다.
- 정답지가 없으면 레퍼런스 3개만으로 한다. 자막 모양(presets)은 레퍼런스에서 가장 비슷한 CapCut 글꼴·크기로 `capcut make-preset`을 떠서 만들고 첫 편집 뒤 사용자 피드백으로 맞춘다.

## ① 수집

- [레퍼런스]는 `[메뉴얼작업폴더]/refs/ref1_<코드>.mp4` 식으로 받는다. 인스타가 "certain audiences"로 막으면 `yt-dlp --cookies-from-browser [로그인 브라우저]`로 다시 받는다.
- 레퍼런스 3개: `/watch`로 다운로드 + 장면 사진(balanced, 100장). 받아쓰기는 mlx-whisper(large-v3-turbo, 한국어, 단어 시간). Gemini 분석은 레퍼런스에만 `--engine gemini`를 붙여 받는다(기본은 local이라 사용자 영상은 구글에 안 올라감). 소리까지 포함한 설명을 받는다.
- [게시본]이 가장 먼저다(공용 규칙 67): 사용자가 실제로 올린 완성 영상 — 정답지 프로젝트와 같은 원본이면 특히. 프로젝트는 게시 전 마지막 판이 아닐 수 있다(한 계정 사례: 프로젝트 판과 게시본의 길이·배속·인트로가 달랐다).
 - `posted_profile.py <게시본.mp4> [메뉴얼작업폴더]/posted --source <원본 영상>` — 길이·장면 박자·밝기·채도·소리 크기·배경음악 여부와 크기·0.5초 장면 사진. 자막 크기·자리(인물 장면/손·제품 장면)·강조 크기·끝 문구 색은 그 사진으로 직접 잰다.
 - 말 배속은 2단계 ①②(받아쓰기·takes.json)를 먼저 해 둔 뒤 `speed_match.py` (아래 정답지 절).
 - 메뉴얼 값 표시 순서: **(게시본) > (정) > (레) > (기본)**. 계정 메뉴얼 0번에서 단계 파일 기본값을 덮으려면 (게시본)이나 (정) 근거가 있어야 하고, (정)과 (게시본)이 다르면 (게시본)을 쓴다. 사용자가 직접 정한 값은 근거 표시(사용자 날짜)만 있으면 덮는다.
 - 새 공용 기능(J컷·시연 시점·장면 리듬·장면별 자막·끝맺음·빼기 ①②)은 계정 메뉴얼 0번 "켜는 공용 기능" 줄에 적은 것만 켜진다 — 게시본에서 그 기법이 보일 때만 적는다(rebuild.sh 옵션도 같이).
- [정답지](사용자가 직접 편집한 CapCut 프로젝트)를 우선 참고한다. 없으면 레퍼런스만으로 한다. 원본은 읽기만 한다.
 - 정답지는 프로젝트 파일과 완성 영상을 둘 다 보고 서로 맞춰 본다. 숫자는 프로젝트 파일(조각·배율·키프레임·자막 글자·색·애니메이션 이름)이 정확하고, 움직임·화면 구성·무엇을 보여 주는지는 영상으로만 보인다(첫 편집 때 숫자표만 보고 "흔들림" 이모지·라벨과 결과 화면 기록을 놓쳤다).
 - 완성 영상: 사용자가 그 프로젝트를 내보낸 파일. 길이가 프로젝트 길이와 같은지 확인한다(편집 전에 내보낸 날것일 수 있다). 없으면 "정답지 프로젝트를 한 번 내보내 주세요" 한 줄로 요청하고 그 사이 프로젝트 파일 분석을 먼저 한다.
 - 영상 보는 법: 0.5초 간격 전체(10×3 타일) + 움직이는 요소(이모지·라벨·전환·확대)는 초당 10~30장으로 잘라 본다. 화면 구성(무엇이 화면을 채우는지, 어디에 무엇이 뜨는지)을 시간대별로 표로 적는다.
 - 프로젝트 파일에서 애니메이션·전환은 이름과 id까지 뽑는다(`material_animations`, `transitions`). 이모지·라벨·메모·큰 자막처럼 모양이 특별한 조각은 `capcut save-template`으로 떠서 `presets/templates/`에 둔다 — 애니메이션까지 따라온다(make-preset은 애니메이션을 담지 못한다).
 - 레퍼런스와 정답지 방향이 다르면 "새 스타일을 들이고 싶으신 건지" 어느 쪽을 기준으로 할지 묻고 따른다.
 - `capcut harvest-enums <프로젝트> --apply` — 사용자가 쓴 효과·전환·자막 애니메이션 이름 학습
 - `capcut make-preset <프로젝트> <자막 id> --out presets/자막_기본.json` — 종류별로 따로(자막_기본, 자막_키워드, 자막_펀치라인 …)
 - 무음 기준값 보정: 정답지의 컷 간격·무음 길이를 재고, `detect-silence`의 threshold·min-silence·pad를 정답지와 같은 결과가 나올 때까지 맞춘다.
 - NG 감지 보정: 정답지 원본 SRT에 `detect-retakes`를 돌려 사용자가 실제로 자른 구간을 잡을 때까지 `--min-words`, `--similarity`, `--window`를 낮춘다(기본값은 영어 기준이라 한국어 짧은 문장을 놓침).
 - 맞춘 값은 메뉴얼 13번에.

### 수집 도구 (scripts/)

- `ref_collect.sh <영상> <출력폴더> <질문.txt>` — 레퍼런스 하나에서 장면 사진·받아쓰기·소리 급등·컷 지점·Gemini 설명을 한 번에. 질문 파일은 메뉴얼 목차 1~11번을 묻게 쓴다.
- 장면 사진: /watch balanced는 장면이 바뀐 만큼만 뽑아 100장보다 훨씬 적게 나올 수 있다(13~27장). 부족하면 ffmpeg로 0.5초 간격 사진을 따로 뽑는다. 사람이 볼 모음 사진은 2초 간격 8×3 타일에 안전 영역 빨간 선을 겹친다.
- Gemini 설명은 장면 사진과 시간대별로 대조한 뒤에만 메뉴얼에 쓴다. 특히 "끝까지 고정" 같은 지속 시간과 글꼴은 0.25초 간격으로 잘라 직접 본다(첫 편집 때 상단 제목을 Gemini 말만 믿고 끝까지 띄웠는데 실제로는 2~3초였다). 자막과 제목 글꼴이 다를 수 있으니 따로 확인한다.
- 소리 급등(spikes)은 효과음 말고도 컷 뒤 말이 다시 시작되는 지점까지 잡는다. 효과음 개수는 Gemini 표를 기준으로 하고 급등은 시간 확인용으로만 쓴다.
- 레퍼런스만으로 잰 효과음 개수는 (추정)으로만 적는다 — 말소리·배경음악 밑에 깔린 작고 귀여운 효과음(뽁·바운스·팝업)은 Gemini 도 소리 급등도 못 잡는다(한 생활용품 계정: 레퍼런스 3편 "0~1개" → 정답지 0.25개/초). 정답지가 없으면 4번 질문에 "효과음을 얼마나 쓰시나요(거의 안 씀 / 글자가 뜰 때마다 / 화면이 바뀔 때마다)"를 넣는다.
- `project_profile.py <정답지 프로젝트> <출력폴더>` — 조각별 시간·배속·배율·키프레임·자막 글자·색·글꼴(fc-scan)을 profile.md로.
- 정답지가 Premiere 프로젝트(.prproj)면 `prproj_profile.py <프로젝트.prproj> <출력폴더> --media <원본 폴더>` — 조각·배속·디테일 확대(배율·위치)·글자(글꼴·글자·떨림 효과)·효과음 시각·중첩 시퀀스(사진 틀·끝 문구)·말 사이 틈(원본 소리로)을 prproj_profile.md로. 완성본 시퀀스를 스스로 고른다(편집 전 고르기 시퀀스가 더 길 수 있다). 글꼴은 그 이름으로 CapCut·확인본에 같은 글꼴을 찾아 넣는다(없으면 글꼴 파일을 받아 설치).
 - 프로젝트는 게시 전 마지막 판이 아닐 수 있다(한 계정 사례: 게시본이 인트로·맞장구를 더 빼고 끝 문구 색을 바꿨다). 같은 원본의 게시본이 있으면 길이·첫 장면·끝 문구·자막 크기·밝기는 게시본으로 다시 재서 (게시본) 표시로 프로젝트 값보다 먼저 쓴다.
 - 말 배속은 프로젝트 값을 믿지 말고 게시본으로 잰다: 2단계 ①②(받아쓰기·takes.json)를 먼저 해 둔 결과폴더에서 `speed_match.py [결과폴더] <게시본.mp4> --audio <편집용 말 영상>` — 문장마다 원본 ÷ 게시본 비율(1.10 = 1.1배)과 0.3초 구간별 값. 구간별 값이 고르면 배속, 한 곳만 튀면 그 자리를 자른 것. (한 생활용품 계정: 프로젝트만 읽고 "1.0배"로 적었는데 게시본은 1.1배였다 — 스킬 편집이 2초 늘어졌다)
 - 색 보정(Lumetri 등)은 ffmpeg 필터로 옮긴 뒤, 게시본과 밝기 통계(`signalstats` 평균·YLOW·YHIGH·채도)를 맞대 같아지게 뒤에 보정 curves 를 붙여 `presets/색보정.txt`에 둔다.
- `calibrate_silence.py`, `calibrate_retakes.py` — 정답지 기준 무음·NG 기준값 찾기. 정답지 원본 영상 경로는 프로젝트의 소재 경로에서 찾는다.
- capcut-cli 결과가 길면 파이프로 받을 때 64KB에서 잘린다 → 파일로 받아서 읽는다.
- 레퍼런스가 사용자 본인 영상일 수 있다. 그러면 정답지와 레퍼런스 차이는 "새로 들인 기법"이므로 어느 쪽을 기본으로 할지 질문에 넣는다.

## ② 분석 — 편집메뉴얼 목차 (고정, 전부 숫자로)

1. 영상 기본 — 길이, 컷 개수, 평균 컷 길이, 배속 여부
2. 훅 규칙(첫 3초) — 첫 자막 시점·모양, 첫 확대, 첫 효과음, 무음 0초 여부, 첫 컷 길이
3. 컷편집 — 컷 스타일, 무음 간격(중앙값·최대), 점프컷 빈도, 소스가 여러 개일 때 장면 바뀌는 타이밍
4. 화면 확대 — 타이밍, 정도(1.0→1.1 등), 지속, 줌인·줌아웃 규칙
5. 자막 — 글꼴 느낌(실제 글꼴 추정, aside로 찾기), 크기, 위치, 그림자, 박스, 외곽선, 한 줄 글자 수, 끊는 단위, 줄 수, 등장·퇴장 움직임, 표시 시간, 강조 방식(색·크기·애니메이션)
6. 자료화면 기본 규칙 — 빈도(개수·평균 간격), 들어오고 나가는 효과와 타이밍(말 시작과의 관계), 분위기, 메인 색 2~3개, 글꼴 1~2개, AI 그림 쓰는 분위기인지. 카드 모양·움직임·도표 형식은 정하지 않는다
7. 인트로·아웃트로
8. 트랜지션 — 종류, 길이, 간격
9. 효과음 규칙표 — 아래
10. 배경음악 — 있는지, 크기(목소리 대비), 들어오고 빠지는 방식. 없으면 "없음"
11. 가리면 안 되는 영역 — 아래 safeZone 숫자 그대로
12. 검수 기준 숫자표 — 평균 컷 길이, 무음 간격, 효과음 개수·초당 빈도, 자료화면 개수·간격, 자막 한 줄 글자 수, 영상 길이
13. 기준값 — 무음 감지·NG 감지 보정값
14. 변경 이력 — 날짜, 바꾼 규칙, 이유

## 효과음 규칙표 만들기

1. 레퍼런스마다 효과음 순간표(시간, 그때 말·화면, 소리 종류, 크기). Gemini 설명 + `scripts/ear_check.py spikes` 결과를 합친다.
2. 소리 종류마다 6가지: 언제 넣나 / 어디에 맞추나 / 팔레트 소리 이름(sfx-catalog.md) / 크기(목소리 대비) / 빈도 제한 / 넣지 않는 경우.
3. 팔레트에 비슷한 소리가 없으면 "이런 느낌의 소리를 팔레트에 추가해 주세요"로 요청.
4. 개수와 초당 빈도를 12번에 숫자로.

## brand.ts

`[Remotion폴더]/src/brand.ts` 한 곳에: 메인 색, 글꼴, 분위기, 자료화면 빈도 기본값, AI 그림 스타일 문구, safeZone.

가리면 안 되는 영역 (1080×1920):
- 위 220px, 아래 420px, 좌우 35px 비움
- 오른쪽 버튼 칸: 세로 990~1500px의 오른쪽 180px 비움 (180px은 추정값, 첫 업로드 뒤 실제 화면 보고 수정)
- 글자·자료화면 핵심은 가로 35~1045, 세로 220~1500 안 (세로 990~1500에서는 가로 865까지)
- 자막도 이 안. 자료화면은 자막 높이와 얼굴을 가리지 않음
- 자막이 세로 990~1500에 있으면 한 줄 폭 650px 이하 또는 중심 x=450. 프리셋 만들 때 이 폭을 글자 수 제한으로 바꿔 적는다
- 배경·사진 가장자리는 넘어가도 됨(글자와 핵심 요소만 지킴)
- 검수 때 장면 사진에 이 영역을 빨간 선으로 겹쳐 확인

```tsx
export const safeZone = {
 top: 220, bottom: 420, side: 35,
 rightButtons: { fromY: 990, toY: 1500, width: 180 },
};
```

## ③ 문서 작성 → ④ 질문

## 메뉴얼 → 단계 파일 연결 확인

메뉴얼에 적은 기법마다 2·3단계 어느 절차·스크립트가 그것을 넣는지 짝을 적는다. 짝이 없는 규칙은 실제 편집에 안 들어간다(첫 편집 때 이모지·라벨 흔들림 규칙과 프리셋이 있었는데 3단계 절차가 아이콘을 Remotion으로만 넣어 한 번도 안 쓰였다).

## 정답지 대조 — 오답노트

정답지와 같은 원본을 편집했을 때(또는 사용자가 "정답지랑 비교해" 할 때) 4단계 뒤에 한다.
1. 위 "정답지는 프로젝트 파일과 완성 영상을 둘 다" 방식으로 정답지를 다시 본다. 이번 편집도 확인본을 같은 간격으로 뽑아 나란히 둔다.
2. 비교 항목: 테이크 선택 / 배속 / 확대 / 자막(끊기·색·크기·글 다듬기·메모) / 이모지·라벨(무엇에·크기·움직임·길이) / 화면 기록(무엇을·언제·얼마나·어떻게 짚나) / 전환 / 길이.
3. `[결과폴더]/오답노트_<정답지>대조.md`: A 크게 다른 것, B 값만 고치면 되는 것, C 정답지엔 없지만 레퍼런스·사용자 지시로 넣은 것(오답 아님), 놓친 이유, 스킬에 반영할 것(승인 대기).
4. 사용자에게 쭉 설명하고 승인을 받은 뒤에만 메뉴얼·단계 파일·스크립트에 반영한다.
