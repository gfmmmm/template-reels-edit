# [4단계] 결과 제출

0. 3단계 ③-E CapCut 실물 검수(승인본 기준)를 통과한 내보낸 영상만 "완성"이라고 한다. 확인본·최종본_고화질은 승인용 그림일 뿐 업로드용이 아니다.
1. 결과물: 편집이 끝난 CapCut 프로젝트 + 승인본(`preview/승인본_기준.mp4`). 업로드용 mp4는 CapCut 실물로 — 영어판이고 사용자가 손을 뗄 수 있으면 `capcut_export.py`, 아니면 사용자가 CapCut에서 내보낸다.
2. `open`으로 결과폴더와 확인본을 같이 띄운다.
3. 쉬운 말로 브리핑: 영상 길이, 컷 수, 자료화면 수(AI 그림 수 포함), 효과음 수, 판단이 갈린 컷(진행상황.md에 모아 둔 것 — 2단계는 중간 보고를 안 하므로 여기서 처음 알린다), 검수 요약 세 줄, 다음에 하실 일("CapCut에서 열기 → 재생 → 저장 → 내보내기 → 내보낸 파일 경로 알려주기"). 브리핑 끝에 최종 풀스크립트(`풀스크립트.md` — 2단계 끝 형식: 대사·이모지·자료장면·상단 제목, 뺀 문장은 제자리 취소선) 전문을 붙인다.
4. 내보낸 파일이 오면 (CapCut에서 사용자가 직접 고친 게 있으면 그 차이는 의도로 보고 고치지 않는다 — 글자를 바꿨거나 크기를 바꿨으면 먼저 확인) `scripts/final_check.sh [결과폴더] <프로젝트> <내보낸 파일>` — 승인본 대조(글자 크기 전수·싱크·규격)를 통과해야 소리 마무리까지 해서 같은 폴더에 `<이름>_업로드용.mp4`. 실패하면 3단계 ③-E 4번으로.
 - 소리 마무리(finish_audio.sh)는 화면은 다시 압축하지 않고 소리만 리미터 + -12 LUFS(공용 규칙, 계정이 바꾸려면 `presets/음량.txt`), 최고 -1.5 dBTP로 다듬는다. 효과음을 들리게 넣으면 목소리 최고점과 겹치는 순간 -1 dBTP를 넘기 쉽고, 효과음을 더 낮추면 안 들리기 때문이다.
 - 퍼센트 막대가 떠 있는 동안은 text_size_check가 자막 띠만 잰다(막대 카드를 자막으로 오인하지 않게).
 - 자동 검수가 통과해도 눈 대조(같은 시각 12~14장면 나란히)를 반드시 한다 — 제목 그림자 얼룩·흰 화면 끼어듦은 숫자 검수로 안 잡혔다(한 편집 사례).
 - 보고: `최종검수.md` 요약(글자 크기 n/n, 싱크, 규격, 음량) + 업로드는 `_업로드용` 파일로.
5. 진행상황.md에 "완료".
5-1. 정답지와 같은 원본을 편집했으면 1단계 파일의 "정답지 대조 — 오답노트"를 한다(정답지 완성 영상 + 프로젝트 파일 둘 다). 사용자에게 설명하고 승인받은 것만 반영.
6. 아쉬운 점 피드백:
 - 기존 규칙과 충돌하는지 먼저 확인. 충돌하면 어느 쪽을 남길지 한 번 묻고 덮어쓴다(추가만 하면 모순이 쌓임).
 - 갈 곳: 색·글꼴·안전영역 → brand.ts / 자막 모양 → presets/·presets/templates/ / 나머지 → 편집메뉴얼. 변경 이력은 메뉴얼 14번에만(날짜·바꾼 규칙·이유).
 - brand.ts나 Remotion 컴포넌트를 고쳤으면 `scripts/remotion_backup.sh` 한 번 — 스킬 안 `remotion/` 사본(드라이브 백업·이식용)을 갱신한다.
7. 어느 계정에나 가는 규칙은 `공용규칙.md`에 모여 있다(사용자가 "공용"으로 정한 피드백, 지키는 파일까지 적힘). 새 피드백이 "공용"이면 단계 파일·스크립트에 넣고 `공용규칙.md`에 한 줄, "개인"이면 편집메뉴얼·presets에.
8. 다른 계정·컴퓨터로 옮기는 일은 운영자 스킬 `/릴스편집이식`이 한다(옮길 것 = 단계 파일·scripts·에이전트·틀·효과음 파일·Remotion 소스, 옮기지 않을 것 = 편집메뉴얼·brand.ts·presets·환경.md). 이 스킬에 새 규칙을 넣을 때는 계정 전용 값(정답지 이름, 글꼴 이름, 색 값, 이 컴퓨터 경로)을 단계 파일이 아니라 편집메뉴얼·brand.ts·환경.md에 적는다 — 단계 파일은 어느 계정에나 맞는 문장만.
